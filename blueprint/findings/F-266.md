# F-266 - A content write that lands during a site deletion likely ends in an unhandled 500

**Found:** 2026-10-05 by review (scope: current; lens: every lens; via reviewer)
**Why it matters:** This is reasoned from PostgreSQL locking, not run. An editor's insert into `entries`/`media` waits on the `sites` row lock, then fails its `site_id` foreign key (23503), which is uncaught. No orphan rows result. An upload in flight leaves its R2 object behind under `sites/<id>/`, which the spec accepts for a later sweep.
**Suggested fix:** optional. Catch 23503 on `site_id` in `createDraft` and the media insert, and answer 404.

# F-194 - `drop()` returns "full" for a slot naming no column, and throws for an index past the column's children

**Found:** 2026-10-03 by review (scope: current; lens: every lens; item 14b, autopilot, reviewer subagent)
**Why it matters:** A bad slot would be announced as the 200-block cap, or crash with a RangeError. `slotAt` cannot produce one today, but `drop`/`DropSlot` are the contract 14c builds on (section slots).
**Suggested fix:** Return a distinct result (`null` or `"invalid"`) and reject `slot.index > childCount`; two unit tests.
**Resolution:** closed by build 2026-10-04 (drag tidy fix, Step 1). `drop()` returns `"invalid"` for a slot naming no column or an index outside 0 to the column's child count; `hoverAnnouncement` says "release to cancel" and a release cancels. Tests in block-drops.test.ts ("drop refuses a slot naming no column", "... an index past the column's children", "... a negative index", "hover over an invalid slot says release to cancel"): red against the old code (`actual: 'full'`, `RangeError: Index 2 out of range`, `actual: 'dropped'`, `actual: 'You can have at most 200 blocks.'`), green with the repair; `npm test` 412/412.

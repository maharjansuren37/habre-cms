# F-301 - optimise-media's GIF branch can re-create an object for a row deleted meanwhile

**Found:** 2026-10-07 by review (scope: current; every lens; via reviewer)
**Why it matters:** The GIF is re-written before the guarded update and the update's count is ignored, so a row deleted in between leaves its object back in R2 with no row.
**Suggested fix:** Check the update's count and delete the key when it is 0, as the resized branch does.

# F-111 - The placeholder's site-title test uses the default title, which is also the code's fallback, so it cannot catch a broken title lookup

**File:** e2e/public-site.spec.ts:44-57; app/features/public-site/home.tsx:39-41
**Found:** 2026-09-29 by review (scope: current; lens: tests)
**Why it matters:** `HomePlaceholder` reads the title with `useRouteLoaderData(...)?.settings.siteTitle ?? "Habre CMS"`. The test expects an `h1` of "Habre CMS", and that is also `DEFAULT_SITE_TITLE` in `e2e/helpers/site-settings.ts:3`. If the route id were wrong, or the layout data changed shape, the fallback would render the same text and the test would still pass. Today the id is correct: it follows the same convention as `settings.tsx`'s `"features/admin-shell/layout"`.
**Suggested fix:** In the placeholder test, set a distinct site title, for example through `withDatabase` (restored in `afterEach`), and assert on that. Mind F-103: this adds one more test that writes the shared row.
**Resolution:** Fixed in tidy-findings Step 4 (2026-10-02, autopilot): home placeholder throws when layout data is missing. Mutation: lookup pointed at a wrong route id failed the placeholder test; reverted. Review 2026-10-02: repaired; stays fixed (autopilot never closes its own repairs).

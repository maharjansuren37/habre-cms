# F-353 - `start` is not a reserved page slug, so a page called "Start" can never be seen on its site

**Found:** 2026-10-07 by review (scope: current; lens: all; via reviewer)
**Why it matters:** Item 18b3 made `/start` a platform path; on a site host every platform path redirects to the platform. A page titled "Start" gets slug `start`, so `<site>/start` sends visitors to onboarding while the menu and sitemap link to it. 18b4's apply can create such pages from AI titles.
**Suggested fix:** Add `"start"` to `RESERVED_PAGE_SLUGS`, with a unit test that every top-level `isPlatformPath` root is a reserved slug.
**Resolution:** fixed by build (autopilot), 2026-10-07: `"start"` added to `RESERVED_PAGE_SLUGS`. Test "a page titled Start gets the numbered address, because /start is onboarding (F-353)" in `app/features/content/slug.test.ts` - red before (`actual: 'start'`), green after; `npm run verify` exit 0, 902 pass. `createDraft` is the only place a page slug is made. A page already stored as `start` is not renamed (v1's `0009` deletes every entry). Awaiting re-review.

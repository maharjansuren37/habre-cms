# F-268 - The slot test's lock poll counts waiting locks across the whole database, so the reverted code could pass it

**Found:** 2026-10-05 by review (scope: repair commit 5d85c66; lens: tests; via reviewer)
**Why it matters:** `select count(*) from pg_locks where not granted` counts any waiting lock, including ones from the other worker's specs. The `>= 2` check can be met before both deletions wait, and then, with F-265's repair reverted, the sign-in could run before the slots are taken and pass without proving anything. Harmless when green.
**Suggested fix:** read `pg_backend_pid()` in the holder transaction and count only waits on that backend's locks (`tuple` on `sites`, or `transactionid` held by that pid).

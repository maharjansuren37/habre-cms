# F-219 - The isolation spec never tests the pooled-connection claim or cross-site update and delete

**Found:** 2026-10-04 by review (scope: current; reviewer subagent, item 15a); lens: tests
**Why it matters:** "A pooled connection never carries `app.site_id`" is load-bearing and untested (no-site checks use a fresh connection); UPDATE/DELETE of another site's rows and an UPDATE moving a row to another site (`with check`) are untested - only INSERT is.
**Suggested fix:** On `postgres(url, { max: 1 })`: a transaction setting site 2, then a plain count on the same connection expecting 0; inside a site-2 transaction, `update ... where site_id = <site 1>` affects 0 rows and `update ... set site_id = <site 1>` fails with the RLS error.

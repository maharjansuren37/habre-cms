# F-119 - Section ids are not checked for uniqueness or for characters the editor's selector can take

**File:** app/features/blocks/blocks.ts (`sectionBlock`, `sectionsSchema`); app/features/blocks/sections-editor.client.tsx:45-70, 96
**Found:** 2026-10-01 by review (scope: current; lens: quality, security)
**Why it matters:** The server accepts any 1-64 character storable string as a section id, repeated or not (OWASP Top 10:2025 A06 insecure design: a trust boundary validated for shape, not for what the client then depends on). With two equal ids, `readerFor` hands both editors one reader, so a save reads the last-mounted editor twice and silently replaces the first section's content; an id holding `"` or `\` makes the `querySelector` that restores focus throw after a move or add. The editor never makes such ids; a hand-built request does.
**Suggested fix:** In `sectionsSchema` add a refine that section ids are unique, and restrict the id to a safe class (e.g. `/^[A-Za-z0-9_-]+$/`, which `crypto.randomUUID()` and the fixtures satisfy) - or build the focus selector with `CSS.escape`. Add a unit test for a duplicate id and for an id with a quote.
**Resolution:** fixed 2026-10-01. `sectionBlock` ids restricted to `[A-Za-z0-9_-]`, `sectionsSchema` refuses duplicate ids; tests added in `blocks.test.ts`. `npm run verify` passes (259 tests).

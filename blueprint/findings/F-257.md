# F-257 - The `saved=email` banner names whoever is signed in, not the account that confirmed

**Found:** 2026-10-05 by review (item 15e1; scope: current; lens: every lens; reviewer subagent)
**Why it matters:** A's confirm link opened in a browser signed in as B lands B on their own page reading "Your email is now b@...", which suggests B's email changed.
**Suggested fix:** Show the address only when the session user is the one who confirmed (e.g. carry the user id and compare, else a neutral "The email was changed."), or accept and document it.

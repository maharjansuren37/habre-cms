# F-103 - Browser specs share the one `site_settings` row, and two of them running at once can fail each other

**File:** e2e/home-page.spec.ts (whole file); playwright.config.ts:23 (`workers: 2`)
**Found:** 2026-09-28 by review (scope: current; lens: tests)
**Why it matters:** `home-page.spec.ts` sets a home page, which takes over `/` for every spec running at the same time. `public-site.spec.ts` asserts on `/`, and a settings save elsewhere can submit this spec's page id after it has been deleted. Seen once during item 9's build: running `home-page` and `manage-settings` together failed the logo test's save, while running them one at a time passed 8/8. Three full runs afterwards were 97/97. The same risk already existed for navigation (item 7b); this item adds a more visible case.
**Suggested fix:** Run the specs that write `site_settings` without overlap. For example, give them a Playwright project that `dependencies` the rest, or give that group `workers: 1`. Or give tests no shared singleton to fight over.
**Resolution:** Re-examined 2026-09-28 by review (independent reviewer): still open at P2, and wider than first written. `home-page.spec`'s `afterEach` calls `resetSiteSettings()`, which also resets title, logo and navigation, so it can overwrite a manage-settings or site-navigation test partway through, not only one that reads `/`. Re-examined again 2026-09-28: still P2, and wider. The F-105 test also sets `home_page_id`, and F-109's assertion reads `site_title`, which `manage-settings.spec` writes.
Re-examined 2026-09-29 by review (scope: current; all lenses): still open at P2, and wider again. The new `public-site.spec` placeholder test reads `/` and the site title, and both are written by `home-page.spec` and `manage-settings.spec` running alongside it. The full run passed this time (99/99), which does not rule out the race.
Re-examined 2026-09-29 by review (scope: current, F-116): still open at P2, and one test wider. `manage-settings.spec`'s new F-116 title test saves a site title and asserts `/` shows the placeholder, so `home-page.spec` choosing a home page at the same moment can fail it. That is the same race this spec file already had, not a new file joining it. The full run passed (100/100).

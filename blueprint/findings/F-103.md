# F-103 - Browser specs share the one `site_settings` row, and two of them running at once can fail each other

**File:** e2e/home-page.spec.ts (whole file); playwright.config.ts:23 (`workers: 2`)
**Found:** 2026-09-28 by review (scope: current; lens: tests)
**Why it matters:** `home-page.spec.ts` sets a home page, which takes over `/` for every spec running at the same time. `public-site.spec.ts` asserts on `/`, and a settings save elsewhere can submit this spec's page id after it has been deleted. Seen once during item 9's build: running `home-page` and `manage-settings` together failed the logo test's save, while running them one at a time passed 8/8. Three full runs afterwards were 97/97. The same risk already existed for navigation (item 7b); this item adds a more visible case.
**Suggested fix:** Run the specs that write `site_settings` without overlap. For example, give them a Playwright project that `dependencies` the rest, or give that group `workers: 1`. Or give tests no shared singleton to fight over.

# F-95 - A page deleted after being linked reverts its row to "No page" with no visible warning, and blocks Save on a row the admin never touched

**File:** app/features/settings/settings.tsx:222-231 (the page `<select>`'s `defaultValue={row.pageId}`); app/features/settings/navigation-form-input.ts:102-104 (`draftRowsToNavItems`'s "neither" refusal)
**Found:** 2026-09-23 by review (scope: changed, item 7b; lens: quality) - confirmed live via a real save-then-delete-then-reopen sequence, not a hypothesis
**Why it matters:** Saved a menu item through the real UI pointing at a page, then deleted that page (the same thing an editor deleting an old page from `/admin/pages` would do). Reopening `/admin/settings`: the row's Label still reads the saved label ("Temp"), but the page `<select>` shows **"No page"** - standard HTML behavior when `defaultValue` matches no `<option>` (the deleted page is no longer in `listPagesForNav()`'s result) - with nothing in the UI indicating anything changed. Clicking Save without touching that row fails with "Item 1: choose a page or type a web address" - `draftRowsToNavItems` correctly refuses a row with a label but neither target, but from the admin's side this reads as an inexplicable error on a row they had no reason to think was broken, and it blocks saving **the whole form**, including an unrelated title or logo change they may actually have been trying to make. Compare the *page not published* case, which the row already surfaces explicitly ("Not published - hidden from visitors" - `settings.tsx:230`); a deleted page gets no equivalent notice. Not reachable through a crafted request - only through ordinary use of the product (delete a page that happens to be in the menu) - but the underlying `pageId` is deliberately not a foreign key (current-work.md's Data and contracts, matching D60/D61's precedent for image blocks), so this can only be caught in the UI layer, not the database.
**Suggested fix:** When a row's `pageId` is set but not found in `pages` (mirroring the existing not-published check), show an inline note such as "This page no longer exists - choose another or remove this item," so the admin sees *why* before they hit Save rather than after.
**Resolution:** Fixed in tidy-findings Step 3 (2026-10-02, autopilot): a menu row whose page is gone shows the note. e2e site-navigation.spec.ts deleted-page test red before, green after. Review 2026-10-02: partly repaired - remainder is F-140.

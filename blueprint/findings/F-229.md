# F-229 - The media and settings `afterEach` in `sites.spec.ts` can leave site 3 behind after a failed setup

**Found:** 2026-10-04 by review (scope: e2e/sites.spec.ts, the F-218 repair; reviewer subagent, item 15a); lens: tests
**Why it matters:** `deleteSite(otherSiteId)` runs last. If `beforeEach` failed on the first test (`siteOneAuthor` is undefined, so `.email` throws at :308), or an earlier cleanup step throws, site 3 and its settings row stay in the dev database. It happens only after a failure, and is the same kind of problem as F-225.
**Suggested fix:** Put the cleanup in `try/finally`, with the `deleteSite` calls in `finally`, each guarded by `if (id)`.

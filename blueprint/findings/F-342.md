# F-342 - The spec understates the `max_tokens` trade-off

**Found:** 2026-10-07 by review (scope: c59b1aa; lens: every lens; via reviewer)
**Why it matters:** "Worst case two to three minutes" holds only for one attempt on the default model; and 8000 tokens (~30,000 characters of JSON) cuts off at about a fifth of the proposal's bounds (~45,000 tokens), not "near every upper bound" - typical runs use ~1,700. The `length` test asserts the code but not that the cost is carried.
**Suggested fix:** Reword both ("for the default model, one attempt"; "about a fifth of the bounds, typical runs ~1,700"); optionally a brevity line in `INSTRUCTIONS`; add `assert.equal(error.costUsd, ...)` to the length test.

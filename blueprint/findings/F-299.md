# F-299 - The "upload itself is not kept" browser assertions cannot fail

**Found:** 2026-10-07 by review (scope: current; every lens; via reviewer)
**Why it matters:** The key filter runs over the array the test built itself, and the flat key `<directory>.jpg` is not where a stored original would land (a fresh UUID), so the 404 is guaranteed. A regression that also stored the original would pass.
**Suggested fix:** List `sites/<siteId>/` with S3 ListObjectsV2 in the test; assert exactly the expected keys after upload and none after delete.

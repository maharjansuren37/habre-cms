# F-334 - The security definer sweep's search_path omits `pg_temp`

**Found:** 2026-10-07 by review (scope: current; lens: every lens; via reviewer)
**Why it matters:** With `pg_temp` unlisted PostgreSQL searches it first for relations, so the app role could shadow `ai_runs` with a temp table and make the sweep a no-op (no privilege gain). PostgreSQL's docs recommend listing it last.
**Suggested fix:** `set search_path = pg_catalog, public, pg_temp` (or qualify `public.ai_runs`). 0020 is applied only to development; editing it plus a hand re-apply there, or a new migration - say which.

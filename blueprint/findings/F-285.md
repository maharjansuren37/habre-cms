# F-285 - The root-run `chown` of Caddy's access logs follows symlinks

**Found:** 2026-10-06 by review (scope: current, item 16b; every lens; reviewer subagent, in an autopilot run)
**File:** deploy/setup-server.sh (`CADDY_LOGS` loop in `install_caddy_site`)
**Why it matters:** A compromised Caddy process could replace a log with a symlink to a root-owned file; the next setup run as root hands that file to `caddy`. Pre-existing for one log; 16b extends it to the second.
**Suggested fix:** `[[ -L $caddy_log ]] && fail ...` before the chown, or `chown --no-dereference`.

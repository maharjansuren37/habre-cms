# F-284 - The restart check falls back to a reload when caddy's start time cannot be parsed

**Found:** 2026-10-06 by review (scope: current, item 16b; every lens; reviewer subagent, in an autopilot run)
**File:** deploy/setup-server.sh (`started=$(systemctl show -p ActiveEnterTimestamp ...)`, `date -d`)
**Why it matters:** If `date -d` cannot parse the timestamp (an unknown zone abbreviation), the arithmetic errors inside the `if`, `restart` stays false and Caddy is only reloaded - the running process keeps an empty token and the wildcard certificate fails.
**Suggested fix:** Use `systemctl show -p ActiveEnterTimestamp --value --timestamp=unix caddy` and strip the `@`; treat any parse failure as `restart=true`.

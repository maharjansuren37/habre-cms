# F-107 - A Save with no `homePageId` field silently resets `/` to the latest posts

**File:** app/features/settings/settings.tsx:57 (`String(form.get("homePageId") ?? "")`)
**Found:** 2026-09-28 by review (scope: current; lens: quality; independent reviewer)
**Why it matters:** A missing field is treated the same as choosing "Latest posts". So a Save from a settings tab opened before this release (whose form has no select), or a scripted post, clears a home page someone else set, and nobody is told.
**Suggested fix:** Tell an absent field (`null`) apart from an explicit `""`. When the field is absent, either leave the home page unchanged or refuse the save with 400.
**Resolution:**
Re-examined 2026-09-29 by review (scope: current; all lenses): still open, at `settings.tsx:57`. D-12 makes the effect more visible: an absent field now resets `/` to the placeholder rather than the post list.

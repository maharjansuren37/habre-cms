# F-261 - `issueEmailToken`'s optional `newEmail` type-checks pairings the database refuses

**Found:** 2026-10-05 by review (item 15e1; scope: current; lens: every lens; reviewer subagent)
**Why it matters:** `email_change` without an address, or `reset` with one, compile and fail only at runtime on `email_tokens_new_email_purpose_check` - safe, not silent, but the type could say it.
**Suggested fix:** Overloads, or a discriminated parameter `{ purpose: "email_change"; newEmail: string } | { purpose: "verify" | "reset" }`.

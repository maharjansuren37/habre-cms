# F-207 - The section and block drag paths share `startDrag` through casts the compiler cannot check

**Found:** 2026-10-03 by review (scope: current; lens: every lens; item 14c2, reviewer subagent)
**Why it matters:** `template` null exactly when `block` is not is a convention; six `as BlockSource` / `as { kind }` casts erase the check, so a later edit reading `block` on the section path compiles and fails at runtime.
**Suggested fix:** Narrow once with a discriminated value, or split the section path's begin/update/release into helpers that hold a non-null template.
**Resolution:** fixed by build (autopilot) 2026-10-04 (drag tidy fix, Step 2). `startDrag` narrows `source` with `"template" in source` at each split (begin, update, onUp); the `template`/`block` locals and every `as BlockSource` / `as { kind }` cast are gone - the grep prints nothing. No behaviour change: `npm run verify` green, block-drag + section-drag specs 28 passed with no test edited. Type-level only, so no red run; left `fixed` for review.

# F-269 - A client-sent `Forwarded: host=` header may override the pinned `X-Forwarded-Host`, and the host now picks the site and the platform

**Found:** 2026-10-06 by review (scope: current, item 16a; every lens; reviewer subagent)
**Why it matters:** `@remix-run/node-fetch-server` reads RFC 7239 `Forwarded` before `X-Forwarded-Host`; the Caddy file pins X-Forwarded-Host/-Proto (D96, F-22) but not `Forwarded`. Since 16a the host decides platform vs site and which site. No exploit found (host-only cookies, CORS preflight, no shared cache) - unverified whether Caddy passes it through.
**Suggested fix:** In item 16b's Caddy file add `header_up -Forwarded` to every `reverse_proxy`; send `Forwarded: host=app.<platform>` to a site host once and confirm no effect.

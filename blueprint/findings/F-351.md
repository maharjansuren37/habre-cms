# F-351 - A failed run through the chain does not record which provider failed

**Found:** 2026-10-07 by review (scope: current, ec70ea9, fingerprint 8a0aebc967fa; lens: every lens; via reviewer)
**Why it matters:** The `AiError`s from `sortChatError` and the Anthropic sorter carry no `provider`, so `ai_runs.provider` is null for every `broken` or `unavailable` failure. With a chain, a 401 from the second provider after a move cannot be told from one from the first, and the adapters' "<P> refused the request" lines have no `runId`.
**Suggested fix:** Put `{ provider: "<id>" }` in the details of every `AiError` both sort functions build; `sortChatError` takes the id as well as the display label.

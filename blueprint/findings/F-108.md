# F-108 - Public loader data now carries entry ids and the home page's id, including a draft's

**File:** app/features/content/entries.server.ts:317-326 (`id`, `isHomePage` on `findPublishedEntry`); app/features/public-site/layout.tsx:30 (whole `settings` returned)
**Found:** 2026-09-28 by review (scope: current; lens: security; independent reviewer)
**Why it matters:** Every public page's hydration data now includes `settings.homePageId`, even when that page is an unpublished draft (D-5 allows choosing one). Page and post data also carry `id` and `isHomePage`, which the view never reads. The impact is low: these are UUIDs behind authenticated admin routes, and nav `pageId`s already leak the same way. It still cuts against 4b's D-5 rule that status is never leaked. (OWASP Top 10:2025 A01, minor exposure.)
**Suggested fix:** Drop `id` and `isHomePage` before `page.tsx` and `post.tsx` return their data. Have the public layout return only the fields the header uses.

# F-333 - Unexpected errors become `broken` with nothing logged

**Found:** 2026-10-07 by review (scope: current; lens: every lens; via reviewer)
**Why it matters:** OWASP Top 10:2025 A10 / A09: a TypeError or non-`APIError` from the SDK is sorted `broken` silently, and an `invalid` schema failure records no field paths - needed when 18b2 compares models.
**Suggested fix:** Log run id, `error.name` and `error.message` in the catch-all; on `invalid`, log the Zod issue paths without values. Never the description.

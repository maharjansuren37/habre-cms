# F-115 - The link allowlist's source file holds raw NUL and DEL bytes, so git and grep treat it as binary

**File:** app/features/blocks/inline-runs.ts:41; app/features/media/media-input.test.ts:43,45
**Found:** 2026-09-29 by review (scope: full; lens: quality, security)
**Why it matters:** `isSafeHref`'s strip regex is written with a literal U+0000 and U+007F (`/[<NUL>-<space><DEL>]/g`), so `git log --numstat` prints `-  -` for this file and every `git diff` of it reads "Binary files differ". This is the file that decides which link schemes reach the public site (OWASP Top 10:2025 A05 injection via `javascript:`), and since `12ff5e1` (item 2b) no pull request has shown a reviewer a line of it. `grep` skips it silently too, and so do the search agents that use it. The regex behaves correctly; the problem is that nobody can see changes to it.
**Suggested fix:** Write the class with escapes, `/[\u0000- \u007f]/g`, keeping the `biome-ignore` (Biome flags escaped control characters too), and use `"a\u0000b"` in the two test strings. Then confirm `git diff --numstat` shows line counts for both files and `npm test` still passes.
**Resolution:** Repaired 2026-09-29 by build (under `autopilot build..review`), on `fix/escape-control-characters`: `4b2a3ab` writes the strip class as `/[\u0000-\u0020\u007f]/g` (the `biome-ignore` is still needed - Biome did not report it unused); `a818dc4` writes the test strings as `"a\u0000b"` / `"a\u0000b.jpg"`. New test `inline-runs.test.ts` "control characters and spaces are stripped before the address is judged" - `/<c>/evil.example` for U+0001, U+001F, space, U+007F is refused, `\u0001#top` accepted - **seen to fail** with `\u007f` dropped from the class (22 pass / 1 fail), passing restored (23 / 0). A byte scan of every tracked text file finds no raw C0/DEL left; `git diff --no-index --numstat /dev/null <file>` counts both files as text; `npm run verify` exit 0, 236 tests. **Note:** these two commits, and the squash-merge, still show both files as binary, since the old side is binary - plain diffs are readable from the next change on. Left `fixed`, not `closed`: autopilot never closes its own repairs, so a person or a later `review` closes it.

# F-302 - optimise-media leaves the old original public if deleting it fails, and never retries

**Found:** 2026-10-07 by review (scope: current; every lens; via reviewer)
**Why it matters:** After a successful update a failed `deleteObject(row.storageKey)` counts the row as failed, but `variant_widths` is set so a re-run skips it; the original (possibly with GPS EXIF) stays at its old URL.
**Suggested fix:** Catch that delete separately, log the key, and count the row optimised with a 'left old object <key>' line.

# F-252 - The confirm test's sign-in helper reads the URL before the login answers, so "the old address no longer signs in" can pass vacuously

**Found:** 2026-10-05 by review (item 15e1; scope: current; lens: every lens; reviewer subagent)
**Why it matters:** `waitForLoadState("networkidle")` returns at once on a settled page and React Router's `<Form>` posts by fetch, so `page.url()` may still read `/admin/login` because the POST has not returned, not because sign-in was refused. That is the only email-on check that the old address stops working; the positive half can flake under CI load (F-251's class).
**Suggested fix:** Wait for the login POST's response before reading the URL, or assert outcomes: `waitForURL("**/admin/posts")` for the new address, the refusal text for the old one.
